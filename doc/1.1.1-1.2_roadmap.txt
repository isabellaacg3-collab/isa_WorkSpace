**1.1.1：只加“Agent 启动入口”**，先别让 iWS 背 Agent 的生命周期、会话、权限、配置这些债。它只负责知道：

“当前 Workspace 是谁 → Agent 可执行文件在哪 → 用什么 cwd/参数启动。”

也就是说它本质上还是个 launcher。右键资源/工作区来个：

> 用 Agent 打开  
> 用 Agent 审查当前项目  
> 用 Agent 继续当前工作

第一版甚至只做“启动 Agent 并把当前工作区路径传进去”都够了。DSHarness/OpenCode 后面谁赢竞标，都不影响 iWS 本体。

然后 **1.2 再做 Git**，这个就明显是 iWS 自己的核心能力了。因为 Git 跟 Workspace 管理是天然一层的：

当前仓库状态、分支、未提交改动、commit、push、历史记录……这些东西 iWS 自己知道，价值很高，而且不依赖某个 AI Harness。

我甚至会这么看版本线：

**1.1.x = 工作区体验补全**
- Agent 启动入口
- 小修小补
- 可移植性/启动体验

**1.2 = Git 成为一等公民**
- 仓库识别
- status
- diff
- add / commit / push
- 分支和日志基础展示

**1.3 之后再考虑 Agent × Git 联动**
比如：
> Agent 读当前 diff  
> 帮我审查未提交改动  
> 生成 commit message  
> 修完后让我确认再提交

这时候就很自然了。

关键是你现在这个决定避免了一个大坑：

**别在 1.1.1 里突然把 iWS 从“工作台”改造成“AI IDE”。**

那会直接 scope 爆炸。

1.1.1 只负责“召唤 Agent”，1.2 把 Git 做牢，之后再决定两者怎么接。
