## isa Workspace V1：移动工作区架构

isa Workspace V1 的核心目标，是解决“多台电脑之间如何持续使用同一套工程文件”这一问题，同时尽可能避免在项目早期引入云同步、个人服务器、自动化 Agent 等额外复杂度。

V1 不建立真正意义上的多端同步系统，而是直接取消“多个工作副本”这一前提：将一块可移动 SSD 作为 Workspace 的唯一主要工作区，工程文件不再分别长期存放于大电脑、小电脑或其他设备中，而是随移动 SSD 一起移动。

因此，V1 的核心思想可以概括为：

**Workspace 跟着人移动，电脑只提供运行环境与计算能力。**

### 一、核心架构

V1 中存在两个主要角色。

第一类是“Workspace 本体”，即移动 SSD。

移动 SSD 中保存所有真正需要长期维护、持续修改和跨设备携带的内容，包括：

- 个人软件工程项目；
- Unity、Qt、Java、C++ 等课程或开发工程；
- Git 仓库；
- 设计文档与开发日志；
- 项目素材；
- 个人脚本与必要配置；
- 其他不可轻易重新获取的工作文件。

第二类是“计算节点”，即实际使用的电脑。

例如：

- 家中的主力大电脑；
- 便携的小电脑；
- 学校机房电脑；
- 未来的其他 Windows 电脑。

这些电脑不再承担“项目文件主存储”的角色，而主要负责：

- 安装和运行 IDEA、Visual Studio、Qt Creator、Unity、UE 等开发工具；
- 提供 CPU、GPU、内存和显示能力；
- 编译、运行和调试项目；
- 保存可重新生成的缓存和临时文件。

因此，从逻辑上看：

**移动 SSD = 个人 Workspace。**

**电脑 = IDE / 编辑器 / 编译器 / 游戏引擎启动器 + 算力节点。**

用户更换电脑时，不再需要考虑“哪台机器上的文件才是最新版”，而只需要将 Workspace SSD 插入目标设备，然后继续工作。

### 二、数据组织原则

V1 应当尽量只在移动盘中保存“有长期价值的数据”，避免将大量可重建文件作为 Workspace 核心内容。

建议长期保存：

- 源代码；
- Assets 或其他原始资源；
- Docs；
- Git 数据；
- 配置文件；
- 项目描述文件；
- 个人制作的脚本与工具；
- 不可重新下载或重新生成的资料。

建议尽量由本机重新生成或忽略：

- Unity Library；
- Temp；
- Build；
- UE DerivedDataCache；
- 编译中间产物；
- IDE 索引；
- 各类下载缓存；
- 可重新安装的软件本体。

这样可以减少大量小文件读写，提高移动工作区的可维护性，并避免 Workspace 因缓存和构建垃圾快速膨胀。

### 三、典型工作流程

在主力电脑上开发时：

1. 插入 Workspace SSD；
2. 从 SSD 中直接打开项目；
3. 使用本机安装的 IDE、游戏引擎或开发工具；
4. 编译和运行过程中产生的临时数据尽量保存在本机；
5. 源码、文档和真实项目资产直接保存回 Workspace；
6. 使用 Git 进行版本记录；
7. 正常关闭工程并安全弹出 SSD。

需要移动到其他设备时：

1. 拔出 SSD；
2. 携带 Workspace；
3. 在另一台环境合适的电脑上插入；
4. 使用该电脑已有的软件环境继续开发。

如果学校机房电脑能够使用 USB 存储设备，并且安装了相应开发环境，那么甚至不需要携带自己的笔记本电脑，只需要携带 Workspace SSD。

### 四、版本管理与备份

虽然移动 SSD 是 V1 的主要工作区，但它不应该成为重要项目在世界上的唯一一份副本。

Git 在 V1 中依然承担关键职责：

- 保存版本历史；
- 支持回滚；
- 防止误删或错误修改；
- 管理分支；
- 为代码提供远程备份。

因此，V1 的基本数据安全结构是：

**Workspace SSD：当前工作副本。**

**Git 远端：关键源码的版本历史与异地备份。**

对于不适合进入 Git 的大型素材、文档或其他数据，可以额外定期复制到另一块硬盘、主电脑或其他备份介质。

### 五、V1 明确不做的事情

为了控制项目范围，V1 不包含：

- 自建个人服务器；
- 自动多端同步；
- NAS；
- Nextcloud；
- Syncthing 网络同步；
- 私人 Git 服务器；
- Docker；
- 自动 CI；
- 自研同步算法；
- 本地或便携 Coding Agent；
- 自动环境部署；
- 跨设备软件配置完全同步。

AI 辅助开发在 V1 中直接使用现有网页版 ChatGPT、DeepSeek、Claude 等服务即可，不专门建设便携 Agent 环境。

V1 的任务只有一个：

**验证“移动 Workspace + 任意计算节点”这一工作模式本身是否真正好用。**

### 六、V1 的成功标准

如果经过一段时间实际使用后，可以做到：

- 工程能够稳定从移动 SSD 中打开；
- 更换电脑时不再需要手动搬运最新文件；
- 不再担心多个版本之间互相覆盖；
- Git 使用正常；
- SSD 性能足够支撑当前 Unity、Qt、Java 等工程；
- 移动办公明显比原来的多端文件管理更方便；

那么 V1 就已经成功。

它不需要成为一个复杂系统。

其价值恰恰来自于：

**用最简单的物理移动方式，消除早期并不必要的分布式同步问题。**

V1 的本质是一次范围受控的软件工程实践：

**先让 Workspace 真正移动起来，再决定是否需要让数据在网络上移动。**
