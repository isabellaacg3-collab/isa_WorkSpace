# Isa Workspace 项目说明

**版本：** V0.1 — 初步设计稿  
**日期：** 2026年11月3日  
**项目类型：** Windows 桌面应用程序  
**开发语言：** Java  
**项目背景：** Java 与面向对象设计课程大作业 / 个人长期软件项目  
**项目状态：** 需求构思阶段，尚未正式开发

---

## 一、项目概述

### 1.1 项目简介

**Isa Workspace** 是一款面向个人学习、软件开发及日常数字资源管理的 Windows 桌面工作台。

项目旨在整合本地文件管理、虚拟工作区、资源关联、快捷操作及开发工具辅助等功能，为用户提供高度个性化、可视化、方便快捷且具备长期拓展能力的数字工作环境。

与传统文件资源管理器不同，Isa Workspace 不仅关注文件在磁盘中的实际存储位置，还关注资源与用户当前工作、学习和项目之间的逻辑关系。

软件允许用户在保留原有文件结构的基础上，自由组织、关联和使用不同位置的数字资源，并通过统一的图形界面提高日常操作效率。

### 1.2 项目定位

Isa Workspace 并非旨在完全替代 Windows 文件资源管理器，也不是单纯的课程资料管理系统。

其定位是：

**以真实文件管理为基础，以虚拟工作区为组织方式，以个性化展示、快捷操作及工具集成为特色的个人数字工作台。**

项目最初以大学课程资料、软件工程和开发项目为主要使用场景，但不将课程管理作为底层架构的限制，以便未来兼容更加广泛的数字资源与使用需求。

### 1.3 长期目标

项目首先作为 Java 课程大作业进行开发，并形成能够实际使用的首个正式版本。

课程验收不是项目的终点。后续将根据真实使用体验持续改进，使其逐步发展为能够长期服务个人学习和工作的软件工具。

## 二、核心设计理念

### 2.1 个性化（Personalization）

允许用户根据不同工作内容和个人习惯组织数字环境。

主要方向包括：

- 自定义工作区名称、图标和资源分组。
- 自由收藏、关联和组织常用资源。
- 根据不同工作区的用途展示不同信息。
- 逐步支持主题、布局及快捷操作的个性化配置。

个性化不仅体现在界面外观，还体现在信息组织和操作流程上。

### 2.2 可视化（Visualization）

将传统的文件路径、项目关系及开发状态转化为直观的图形界面。

通过资源卡片、目录树、工作区面板、状态标识及其他可视化组件，降低用户理解和管理数字资源的成本。

### 2.3 方便快捷（Convenience）

减少文件查找、目录切换、工程启动和资源整理过程中的重复操作。

尽量利用系统已有信息自动填充文件名称、类型及路径，避免不必要的手动登记。

常用操作应尽量通过少量点击、拖拽、右键菜单或快捷搜索完成。

### 2.4 可拓展性（Extensibility）

软件采用适度模块化设计，使核心资源管理功能与其他工具功能保持相对独立。

后续能够在不大规模推翻既有设计的前提下，增加新的资源类型、可视化方式与工具集成功能。

**原则：优先保证当前功能可靠、易用，不为尚未确定的未来需求过度设计。**

## 三、核心概念

### 3.1 Asset（资源）

Asset 是软件管理的基础对象，代表一个可以被用户使用或引用的数字资源。

初步支持的资源对象包括：

- 普通文件，如 PDF、PPT、Word 文档、图片等。
- 文件夹及目录。
- 软件开发工程，例如 Java、Unity 等项目目录。
- Git 仓库。
- 网页链接等非本地文件资源（计划支持）。

每个被注册的 Asset 具有独立标识，并保存名称、类型、位置及其他必要元数据。

**Asset 不等同于单个物理文件。** 一个包含大量文件的软件工程目录，同样可以作为一个 Asset 进行管理。

### 3.2 Workspace（工作区）

Workspace 是用户围绕特定工作目标建立的逻辑资源集合。

例如：

- Java 课程工作区
- ImmuneDefense2D 游戏开发工作区
- 个人作品集工作区
- 通用资料工作区

工作区不必对应某个实际磁盘文件夹。

一个 Workspace 可以包含多个 Asset；同一个 Asset 也允许同时关联多个 Workspace。

### 3.3 文件位置与逻辑关联

Isa Workspace 区分两种关系：

**物理关系：** 文件和目录在 Windows 文件系统中的实际存储结构。

**逻辑关系：** 用户为资源建立的工作区归属、收藏、分类及其他关联。

两者相互配合，但不应混为一谈。

例如，用户可以把某份资料同时关联到两个工作区，而无需在磁盘中复制两份文件。

## 四、主要功能设计

### 4.1 本地文件浏览与管理

提供基础文件管理界面，能够直接访问用户本机的真实文件系统。

计划支持：

- 浏览本地磁盘、文件夹及文件。
- 以列表或图形方式展示目录内容。
- 打开文件、文件夹及其对应程序。
- 新建文件夹、重命名、复制及移动文件。
- 从文件浏览界面直接将资源加入工作区。

文件浏览功能应直接读取文件系统，不要求用户提前登记所有文件。

首版不追求完整复刻 Windows Explorer 的高级功能。

### 4.2 工作区管理

允许用户创建、修改、删除及组织不同工作区。

每个工作区可集中展示相关资源，并允许：

- 新增或移除资源关联。
- 按类别浏览资源。
- 收藏常用资源。
- 快速打开相关文件和工程。
- 查看工作区中的基本资源信息。

工作区管理以逻辑组织为主，不强制改变原文件位置。

### 4.3 Asset 资源索引

建立统一的资源注册与索引机制。

用户可以从真实文件浏览界面直接选取资源，将其加入一个或多个工作区。

软件自动读取可获得的文件信息，用户按需补充名称、描述及分类。

数据库主要保存资源元数据和关联信息，而非复制原文件内容。

软件需要明确区分：

- 从某个工作区移除资源关联。
- 从资源索引中注销资源。
- 对磁盘上的真实文件执行修改。

移除逻辑关联不应造成真实文件被删除。

### 4.4 快捷访问与搜索

提供统一的资源访问入口。

初步考虑：

- 常用工作区快捷入口。
- 收藏资源。
- 最近访问记录。
- 按名称、类型或所属工作区查询资源。
- 通过资源卡片直接启动文件、目录或工程。

搜索首先面向软件管理的资源索引，不要求首版实现完整的磁盘全文搜索。

### 4.5 开发工具辅助

针对软件开发工作区，提供必要的工程操作入口。

初步考虑：

- 快速打开工程目录。
- 使用已配置的开发工具启动工程。
- 识别或关联 Git 仓库。
- 查看 Git 当前分支、工作区改动状态和提交记录。

首版优先考虑 Git 信息的只读展示，不急于实现复杂的版本控制操作。

## 五、典型使用场景

### 场景一：整理课程资料

用户从桌面打开 Isa Workspace，进入 Java 课程工作区。

通过文件浏览功能找到新下载的教学 PPT，选择“添加到工作区”。

软件读取文件名称和路径，用户确认关联后，该资源即显示在 Java 工作区中。

之后可以直接通过工作区打开课件，无需反复寻找实际目录。

### 场景二：跨工作区复用资源

某份参考资料已经登记在资源库中。

用户希望另一个开发项目也能使用它，只需建立新的 Workspace 关联。

多个工作区引用同一份实际资源，无需复制文件，也无需重复登记完整信息。

### 场景三：快速进入软件开发环境

用户在首页选择某个游戏开发工作区。

软件展示相关工程目录、参考资料和 Git 仓库信息。

用户通过快捷入口打开 Unity 工程，或进入项目目录及相关文档。

### 场景四：管理真实文件

用户直接使用 Isa Workspace 浏览本地目录。

在文件视图中执行新建、重命名或移动等常见文件操作，同时可按需将文件关联到现有工作区。

用户不必为了整理逻辑关系而改变真实文件结构。

## 六、首版技术方案（暂定）

| 技术 | 计划用途 |
|---|---|
| Java | 主体开发语言及业务逻辑 |
| JavaFX | Windows 桌面图形界面 |
| FXML / Scene Builder | 可视化界面构建 |
| SQLite + JDBC | 本地资源索引与配置持久化 |
| Java NIO | 文件、目录及路径操作 |
| Java Process API | 调用本地工具及 Git |
| Git | 项目自身版本管理及仓库信息集成 |

采用适度分层设计，区分界面、业务逻辑、文件系统操作与数据库访问等职责。

以上为候选技术路线，具体依赖和工程结构需要在开发准备阶段确认。

## 七、首版范围与限制

### 7.1 首版主要目标

完成一款可以独立启动、具有图形界面、能够管理真实文件和虚拟工作区的 Windows 桌面软件。

优先跑通以下核心操作：

1. 打开软件并浏览本机文件。
2. 创建和管理自定义 Workspace。
3. 将真实文件或目录关联到 Workspace。
4. 保存并重新加载资源及关联信息。
5. 直接打开已管理的资源。
6. 进行基础的资源查询、编辑和移除。
7. 提供必要的个性化设置及常用快捷入口。

基础功能稳定后，再根据开发时间补充 Git 可视化及其他辅助能力。

### 7.2 当前不纳入首版范围

- 跨设备资源同步。
- 云端存储及远程服务器。
- 用户账号及在线协作。
- 完整的 Windows Explorer 替代功能。
- 复杂的 Git 图形客户端。
- AI Agent / MCP 集成。
- 完整插件市场与复杂自由布局系统。
- 大规模自动文件扫描与智能分类。

这些方向可以保留为后续讨论主题，但暂不据此设计首版系统。

### 7.3 数据安全原则

软件应避免误操作导致用户文件丢失。

资源关联的修改默认只影响索引数据。

对于真实文件的移动、重命名等操作，需要提供明确反馈，并尽可能保持索引一致。

当资源路径失效时，应允许用户重新定位，而不是立即删除记录。

首版可暂不提供真实文件删除功能，优先保证已有文件管理操作安全可靠。

## 八、课程大作业适配

Isa Workspace 同时作为《Java 与面向对象设计》课程大作业。

根据课程评分方案，项目需要体现 Java 面向对象设计，并重点考虑业务流程、技术深度、实用性、知识点覆盖和创新性。

项目计划通过以下内容体现课程能力：

- **面向对象设计：** Workspace、Asset 及相关业务对象的建模。
- **接口与多态：** 不同资源操作及服务的适度抽象。
- **JavaFX：** 事件驱动桌面图形界面。
- **JDBC：** 本地数据持久化。
- **文件操作：** Windows 文件系统访问与管理。
- **集合和 Lambda：** 资源集合管理、筛选与排序。
- **异常处理：** 路径失效、文件访问错误及操作失败处理。
- **多线程：** 避免文件读取和耗时任务阻塞图形界面。

项目创新性主要体现在真实文件管理与逻辑工作区的结合，以及面向软件开发场景的快捷操作和资源复用。

不以堆砌技术知识点为目的，优先保证功能之间具有合理的业务联系。

## 九、开发与交付原则

**先可用，再完善；先完成核心流程，再扩展外围能力。**

项目首个正式版本至少应达到：

- 具备可正常使用的桌面图形界面。
- 资源和工作区数据在重启后能够保留。
- 用户能够完成基本文件浏览及资源组织。
- 同一资源能够关联多个工作区。
- 不会因解除逻辑关联而删除原文件。
- 常用操作具有清晰的反馈和错误提示。
- 软件具有可持续维护的基本代码结构。
- 具备适合课程展示的完整操作流程。

课程交付后，项目可继续根据实际使用需求迭代。

## 十一、项目总结

Isa Workspace 的核心价值并非创造新的文件存储体系，而是在现有 Windows 文件系统之上，为用户提供更自由、更直观、更符合个人习惯的数字资源组织和使用方式。

项目将从真实文件管理和虚拟工作区关联出发，逐步整合资源搜索、快捷启动和开发工具辅助等功能。

其长期发展遵循四项核心原则：

**个性化、可视化、方便快捷、可拓展性。**

**项目目标：做一款真正愿意长期使用、能够随着个人需求不断成长的桌面软件，而不只是一份完成后便被弃置的课程作业。**
